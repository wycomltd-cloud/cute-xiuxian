## 上傳方式

先在遊戲「設定與存檔」匯出備份。解壓後，把 index.html、assets、css、js 及說明／授權檔直接覆蓋上傳到 GitHub 專案根目錄，勿多包一層資料夾。等待 Actions 的 Pages 部署成功，再刷新遊戲。

維持 main → /(root)。本包尚未代為上傳你的GitHub。玩家首次刷新載入v1.9.2時會看到此次更新公告，無須清除網站資料或重開。

## 坊市：每次換新整批依原價加價

每日免費初始一批貨品，另可用靈玉換新最多5次，不再每十分鐘免費換新。每日按玩家裝置本地日期重置。

| 當日付費換新次數 | 換新費用 | 本批全品項價格 | 原價1,000靈石的例子 |
|---|---:|---:|---:|
| 初始免費首批 | 0 | 原價 | 1,000 |
| 第1次 | 5靈玉 | 原價＋20% | 1,200 |
| 第2次 | 10靈玉 | 原價＋30% | 1,300 |
| 第3次 | 20靈玉 | 原價＋40% | 1,400 |
| 第4次 | 40靈玉 | 原價＋50% | 1,500 |
| 第5次 | 80靈玉 | 原價＋50% | 1,500 |

第四次未另指定，本版暫按與第五次相同的＋50%實作。

- **整批採相同加價比例，不是隨機折扣。** 每批會按生成時境界與戰力挑選貨品及估出原價，然後套用當次加價。
- 原價仍依商品種類、品階、境界／戰力、賣家性格、關係與既有輪回折讓計算；加價以這個原價為基準，不拿上一批成交價重複複利。
- 丹方與靈玉標價商品也套用本批相同比例。成交價向上取整，最低1單位貨幣。
- 提升戰力或境界後，下一次生成貨架才重新評估；換裝不會立即免費重抽貨品。
- 次數及費用會存檔，刷新、離線、輪回不重置；不足靈玉或第六次換新都不扣款、不耗次數、不換貨。
- 同種成品丹每日限購3顆繼續保留，換新不重置。
- v1.9.1既有貨架按當日已用次數原地改為本批加價，保留貨品、剩餘數量及已售狀態，不額外送一批新貨。已買物品與資源不回溯更動。

## 送禮：不同道友共同累計50次

- 道友固定50位，舊存檔不足會補足，保留原道友與好感關係。
- 每次送出1件未穿戴裝備、丹藥或殘片，成功扣物後全體計數＋1。殘片合計功法袋與通用揹包；鑲嵌寶石隨裝備送出。
- **送給任何道友都算同一個總數**。例如送給甲20次、乙15次、丙15次，全體累計50次便觸發一次回禮。
- 全體第50、100、150……次送禮時，由一位已收過禮且在世的道友立即回禮，不一定是收到第50件禮物的那一位。
- 回禮可能為 **靈石／靈玉／裝備／丹藥／功法殘片**。每滿50次保證一次回禮，種類在可發放的候選中隨機。
- 保留上一版的回禮價值控制：以這50件送禮估值的10%為回禮估值預算，靈石至少1；靈玉每枚按500靈石估值。裝備、丹藥、殘片從當前境界可用、非隱藏且估值不超出預算的品項抽取。低價禮物的一批可能只有部分回禮種類符合預算；不同種類不保證等機率或等價。
- 送禮提高收禮對象好感，每次1～8點，上限100；全體計數與個別好感分開，原道侶條件保留。
- 全體累計數、距下次回禮次數、待領回禮顯示於道友頁。個人詳情同時顯示該位收禮數及全體總數，避免混淆。
- 計數與待領紀錄可存檔，跨日、刷新與輪回不重置。無物品、穿著中的裝備或不存在的禮物不扣物、不計次。

### 舊版送禮紀錄遷移

- 合計所有道友原有 `giftsReceived`，轉成全體總次數。
- 舊版已經發放的每人50次回禮保留為已領紀錄，不會因修正再發一次。
- 合併後若已達全體50次門檻、但舊版因分開計數未發放，會生成待領回禮；道友頁提供「領取待領回禮」，無須額外再送一件。
- 例如甲25次＋乙25次，舊版沒有回禮，更新後可補領1次；甲75次＋乙25次，舊版已發1次，更新後只補缺少的第2次。
- 遷移只執行一次，領取後刷新或讀檔不會重發。

## 其他規則保留

- 鬥法匹配與開戰採和主角相等的切磋基礎戰力，換裝後開戰重新同步。五修剋制與隨機發揮繼續生效；不修改NPC資料卡的真實戰力。
- v1.9的閉關1.3倍、吐納3秒冷卻／每次5秒修為／每日100次後一成、論道每日收益、修為丹境界限制及遞減藥效、靈寵探索收入、每日論劍結算與活動額度均保留。
- 裝備回爐50%材料、裝備出售、丹藥出售及已知購買成本上限保留：坊市購得物品的回收另不超出實付價60%，防止舊折扣商品轉售套利。舊存量無購買紀錄者保留原估價。
- 原有境界男女插畫、女主角長髮、五修法器、相機乾淨全圖、幽默文案與性別設定保留。
